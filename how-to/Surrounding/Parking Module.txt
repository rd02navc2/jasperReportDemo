發票與點數補登模組（Invoice Module）測試計畫與系統流程圖
========================================================================

查詢會員特定日期發票紀錄 (getUserInvoice)】

  前端發起 GET 請求
       |
       |  /getUserInvoice/{sMemberID}/{sDate}  (例如: /.../M12345/2026-06-11)
       v
  InvoiceController (接收 String 參數)
       |
       |---> 呼叫 invoiceService.getUserInvoice(sMemberID, sDate)
       v
  InvoiceService (安全防禦驗證與交易控制 @Transactional(readOnly = true))
       |
       |  執行 java.time.LocalDate.parse(sDate)
       |  將字串成功解析為符合現代架構的 LocalDate 物件
       v
  InvoiceRepository (執行物件導向 JPQL 查詢)
       |  
       |  SELECT t FROM TcPsaFile t
       |  WHERE t.tcPsa13 IN (SELECT l.lpj03 FROM LpjFile l WHERE l.lpj01 = :sMemberID)
       |    AND t.tcPsa04 = :sDate
       |    AND t.tcPsaplant = 'BY001'
       |  ORDER BY t.tcPsa05
       v
  資料庫回傳 TcPsaFile 實體清單 (自動適應 Java 屬性映射)
       |
       |---> Service 接收 List<TcPsaFile> 並向下傳遞
       v
  InvoiceController (型態自動推導，不進行手動強轉)
       |
       |---> 回傳封裝格式 InvoiceDTO.Response.success(data, "查詢成功")
       v
  前端接收 200 OK 乾淨 JSON 回應 (code="0000", yn="Y", data=[...])

   字串日期解析、多表子查詢、JPA 實體映射、交易控制與防禦性錯誤攔截是否完全正常。

3. 測試用例與詳細步驟

   測試用例 01：會員特定日期發票查詢 (getUserInvoice) - 成功情境
   ├─ 預置條件：
   │  1. lpj_file 表存在一筆資料：lpj01='M12345', lpj03='LINK_KEY_001'
   │  2. tc_psa_file 表存在對應資料：tc_psa13='LINK_KEY_001', tc_psa04=to_date('2026-06-11','yyyy-MM-dd'), tc_psaplant='BY001'
   ├─ 測試步驟：
   │  1. 使用 Postman 發送 GET 請求至：
   │     http://localhost:8080/Surrounding/api/invoice/getUserInvoice/M12345/2026-06-11
   │  2. 檢查 API 狀態碼是否為 200 OK。
   │  3. 驗證回傳 JSON 的 code 是否為 "0000"，message 是否為 "查詢成功"。
   │  4. 驗證 data 陣列中是否正確回傳該筆發票實體內容。
   └─ 預期結果：查詢成功，字串日期 "2026-06-11" 在 Service 層成功轉為 LocalDate 並傳入 JPQL 執行，無任何 ClassCastException。

   測試用例 02：發票查詢 - 用戶輸入錯誤日期格式情境（防禦性測試）
   ├─ 預置條件：無。
   ├─ 測試步驟：
   │  1. 故意輸入錯誤格式的日期字串發送請求：/getUserInvoice/M12345/20260611 (少了橫線) 或 /getUserInvoice/M12345/error-date
   │  2. 檢查日誌是否輸出 `DateTimeParseException` 攔截警告。
   │  3. 檢查系統回傳的錯誤格式。

   測試用例 03：新增臨時會員 (addTempMember) - 寫入功能與交易驗證
   ├─ 預置條件：確認 LSM_FILE 資料表目前沒有 center_id='TPE' 且 member_id='TMP888' 的紀錄。

   測試用例 04：新增臨時會員 (addTempMember) - 異常回復驗證 (Rollback)
   ├─ 預置條件：刻意在 Service 中製造 RuntimeException（例如傳入不合法的 null 值或主鍵衝突）。
   ├─ 測試步驟：
   │  1. 觸發帶有錯誤參數的 addTempMember 請求。
