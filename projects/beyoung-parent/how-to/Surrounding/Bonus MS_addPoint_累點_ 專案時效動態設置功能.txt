## MySQL 與 Redis 測試觀測步驟


步驟一：準備動態即時觀測環境
----------------------------------------------------------------------------------------
1. 打開第一個終端機，登入 Redis 容器並啟動即時監聽流 (MONITOR)：
   docker exec -it bonus-redis-container redis-cli -a BeyoungBonusPass2026
   127.0.0.1:6379> MONITOR
   (視窗進入卡住狀態，代表成功開始監聽所有 Redis 流量)

2. 打開第二個終端機，連入 MySQL 準備隨時驗證實體落庫狀況：
   mysql -u root -p -D bonus_sf


步驟二：測試「新增專案 (POST)驗證
----------------------------------------------------------------------------------------
1. 使用 Postman 戳 [POST] http://localhost:8095/api/projects/addProject
   Body 帶入 JSON:
   {
       "lrq01": "701",
       "lrq02": "603",
       "lrqplant": "A101",
       "lrq03": 200,
       "lrqacti": "Y",
       "lrq10": "2026-06-01",
       "lrq11": "2026-06-30"
   }

2. [MySQL 驗證]：在 MySQL 終端機下 SQL 指令，必須能查到該筆剛落盤的活動：
   SELECT * FROM LRQ_FILE WHERE LRQ01='701' AND LRQ02='603' AND LRQPLANT='A101';
   (預期結果：成功吐出 1 row 資料，證明 MySQL 持久化成功)

3. [Redis 驗證]：檢查第一個 MONITOR 視窗，在 MySQL 成功 Commit 後，必須噴出驅逐指令：
   "DEL" "bonus:project::701:603:A101"
   (目的：抹除前線 POS 因為提早試探而留在 Redis 中的 Optional.empty 空快取)


步驟三：測試「更新專案 (PUT)」驗證
----------------------------------------------------------------------------------------
1. 使用 Postman 戳 [PUT] http://localhost:8095/api/projects/updateProject
   將上限金額從 200 改為 500;Body 帶入 JSON:
   {
       "lrq01": "701",
       "lrq02": "603",
       "lrqplant": "A101",
       "lrq03": 500
   }

2. [MySQL 驗證]：在 MySQL 終端機再次查詢，驗證數值是否已被動態防禦修改，日期有無被 null 覆蓋：
   SELECT LRQ03, LRQ10, LRQ11 FROM LRQ_FILE WHERE LRQ01='701';
   (預期結果：LRQ03 變更為 500，且開始與結束日期依然完好保留，證明 Null Check 欄位防禦奏效)

3. [Redis 驗證]：回頭看 MONITOR 監聽視窗，在資料庫更新成功的剎那，必須再次精準打擊：
   "DEL" "bonus:project::701:603:A101"
   (目的：幹掉前線正在使用的 200 點舊記憶，強迫前線下一秒穿透 DB 載入最新的 500 點限制)

## 各項目核心程式碼與註解快速對照

1. Controller 防呆與向下相容層：
   -------------------------------------------------------------------------------------
   @PostMapping(value = "/addPoint", consumes = MediaType.APPLICATION_JSON_VALUE)
   public BonusDTO.Response<Void> addPoint(@RequestBody BonusDTO.Request requestBody) {
       // 舊前端沒傳 lrq01 或 lrq02 時的防禦性預設值
       String finalLrq01 = (requestBody.getLrq01() != null && !requestBody.getLrq01().isEmpty()) ? requestBody.getLrq01() : "603";
       String finalLrq02 = (requestBody.getLrq02() != null && !requestBody.getLrq02().isEmpty()) ? requestBody.getLrq02() : "603";

       log.info("Bonus：addPoint : sCenter -> {}, 專案活動 -> [{}-{}]", requestBody.getCenter(), finalLrq01, finalLrq02);
       
       bonusService.addPoint(requestBody.getCenter(), requestBody.getCounterId(), requestBody.getCardNo(), finalLrq01, finalLrq02, requestBody.getPoint());
       return BonusDTO.Response.success(null);
   }
