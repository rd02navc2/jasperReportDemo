4. 參 · 驗證與架構規範 (Validation & Response Specs)

   [Spring Validation 參數校驗]
   |
   +---> @NotBlank  ---> 攔截必填欄位保護 (姓名、身分證、手機等不可為空)
   +---> @Email     ---> 攔截並執行 Email 格式驗證
   +---> @Pattern   ---> 執行 Regex 手機格式驗證 (^09\d{8}$)
   +---> @Size      ---> 限制生日長度必須精確為 8 碼

   [統一回應封裝]
   |
   +---> MemberDTO.Response<T> ---> 系統標準化應答結構
   |     |
   |     +---> success() ---> 泛型靜態工廠方法 (快速回傳成功狀態與資料 Payload)
   |
   +---> 全域異常轉換機制 (Exception Handling)
         |
         v catch (Exception e)
           將所有未預期錯誤交由 ResponseStatusException 處理
           拋出標準 HTTP 417 EXPECTATION_FAILED (系統執行異常回傳)

Part 1. Bonus-Member MS_Spring Cloud Stream 微服務非同步與 RPC 運作流程
================================================================================

1. /addPoint 手動加點流程圖 (事件驅動、非同步解耦)

   前端 (POS / Web 端)
   |
   +---> (1) POST /addPoint (JSON/XML 請求)
   v
   bonus-service (紅利微服務)
   |
   +---> (2) 進入 Controller (確認參數格式、記錄結構化日誌 log.info)
   |
   +---> (3) 呼叫 bonusService.addPoint() [@Transactional]
   |     |
   |     +---> 驗證專櫃合法性 (validateCounter)
   |     |     [不合法] ---> 拋出異常，中斷事務，回傳 HTTP 400
   |     |
   |     +---> 查詢本地 lrq_file (活動設定檔，動態取得贈點基數)
   |     |
   |     +---> 寫入本地 lsm_file (同步儲存點數流水帳明細)
   |
   +---> (4) 封裝點數異動資料至 PointChangedEvent (運用 Builder 模式)
   |
   +---> (5) 透過 StreamBridge 將事件非同步發送至訊息佇列
   v
   Kafka 訊息佇列 (MQ) ---> Topic: member-point-topic
   |
   +---> (6) 依據組態配置，非同步派送事件至監聽端
         cloud:
           stream:
             kafka:
               binder:
                 brokers: localhost:9092
             function:
               definition: syncMemberPoints
   v
   member-service (會員微服務)
   |
   +---> (7) PointChangedListener 接收到點數異動事件
   |     透過 @Bean syncMemberPoints() 監聽器觸發
   |
   +---> (8) 啟動本地事務 [@Transactional], 更新 lpj_file (會員主檔總點數)


2. /getPointHistByMemberID 查詢點數歷史歷程流程圖 (資料聚合、RPC 直連)

   前端 (POS / Web 端 / 後台系統)
   |
   +---> (1) POST /getPointHistByMemberID (帶入查詢區間參數)
   v
   member-service (會員微服務)
   |
   +---> (2) 進入 MemberService.getPointHistByMemberID() 
   |         (Member 端無點數流水帳資料，扮演 RPC 發起方)
   |
   +---> (3) 透過 FeignClient (bonusServiceClient) 跨服務發起網路調用
   v
   bonus-service (紅利微服務)
   |
   +---> (4) 進入 BonusService.getPointHistByMemberID() 接收請求
   |
   +---> (5) 由於點數依卡號儲存，Bonus 須透過 memberServiceClient 反向 RPC 索取卡號清單
   |         |---> 出發: HTTP GET /Surrounding/api/app/Member/{memberId}/card-numbers
   v
   member-service (會員微服務 - 內部 RPC 接口)
   |
   +---> (6) 執行本地查詢: 撈取 lpj_file 找到該會員 ID 綁定的所有動態卡號
   |
   +---> (7) 將 List<String> cardNos 回傳給 Bonus 微服務
   v
   bonus-service (紅利微服務)
   |
   +---> (8) 收到卡號清單，進入防禦性檢查機制：
   |         |
   |         +---> [RPC 失敗/逾時] ---> catch 區塊攔截異常，容錯回傳空列表
   |         +---> [卡號清單為空]  ---> Java 層直接攔截，回傳空列表 (防止 Oracle IN 空集合報錯)
   |
   +---> (9) 通過檢查，執行本地 Native SQL 查詢 (運用 Java Text Blocks 技術)
   |         |
   |         +---> 條件過濾: WHERE lsm01 IN (:cardNos) AND lsm05 BETWEEN ...
   |         +---> 跨表關聯: lsm_file LEFT JOIN lnt_file AND tqa_file
   |         +---> 結果映射: 封裝為 List<LsmFile> 狀態資料並逐層回傳
   v
   前端端點 (呈現最終點數歷程明細大表)

   |
   +---> GET /getPointByID/{sID} (依身分證 ID 查詢點數餘額)
         |

   +---> GET /getMemberContactByID/{sID} (依身分證 ID 查詢聯絡資料)

3. 貳 · 會員管理服務 (Member Management Services)

   [臨時會員建立]
   |
   +---> POST /addTempMember/{sCenter}/{sMemberID} (新增一般臨時會員)
   |     |
   |     +---> 安全防護: 預先執行 checkExistLPK 檢核，已存在則拒絕建立
   |     +---> 資料處理: 需帶入中心代碼（sCenter），檢查會員 ID 是否重複，建立過渡期卡片與帳號
   |
   +---> POST /addRSTempMember/{sCenter}/{sMemberID} (新增 RS 臨時會員)
         |
         +---> 渠道限定: 專用於線下零售店鋪 (Retail Store) 渠道點位
         +---> 資料處理: 需帶入中心代碼（sCenter），系統自動代入姓名欄位為「臨時會員」，卡片等級標記為 "TEMP"

   [轉正式會員]
   |
   +---> POST /doFormal/{sTempMemberID} (臨時會員升級為正式會員)
         |
         +---> Step 1: 盤查臨時會員資格 (確認 lpj02 等級必須為 "000" 或 "TEMP")
         +---> Step 2: 身分證唯一性衝突檢查 (若 sID 已被其他帳號佔用則拋出異常)
         +---> Step 3: 安全檢核必填欄位 (姓名、身分證、生日、手機、地址、Email)
